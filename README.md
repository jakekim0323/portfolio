# 📌 Project 01
# ☕ Cafe Kiosk & Chat Application

### 프로젝트 개요

데이터베이스 실습 과정에서 C#과 MySQL을 활용하여 카페 키오스크 프로그램을 제작했습니다.
이후 6명의 팀원과 함께 카카오톡과 유사한 채팅 애플리케이션을 개발했으며, Azure 클라우드 서버를 활용해 서로 다른 PC 간 실제 메시지 송수신이 가능하도록 구현했습니다.
이 프로젝트를 통해 처음으로 클라이언트, 서버, 데이터베이스가 연결되어 하나의 서비스로 동작하는 구조를 경험했습니다.

### 사용 기술
- C#
- MySQL
- Microsoft Azure
- Database
- Client / Server Communication

### 주요 구현 기능
- 회원가입
- 로그인
- 회원정보 MySQL 저장
- 등록된 회원정보 기반 로그인 처리
- 카페 메뉴 조회 및 주문
- 사용자와 관리자 계정 구분
- 권한에 따른 기능 분리
- 총 관리자 전용 관리 기능
- 데이터 조회 및 수정
- 채팅 애플리케이션 구현
- Azure 서버 구축 및 실행
- 서로 다른 PC 간 메시지 송수신

### 구현 과정
카페 키오스크에서는 사용자가 회원가입을 진행하면 개인 정보를 MySQL에 저장하고, 저장된 데이터를 기반으로 로그인할 수 있도록 구현했습니다.
일반 사용자와 관리자 계정을 구분했으며, 기본적인 화면과 기능은 유사하게 구성하되 총 관리자에게는 서비스 운영을 위한 별도의 권한을 부여했습니다.
이를 통해 단순 UI 구현을 넘어 사용자 데이터 저장, 로그인, 데이터 조회 및 수정, 권한에 따른 기능 제어 등 실제 서비스에서 사용되는 데이터 처리 구조를 경험했습니다.
채팅 프로그램에서는 처음에는 한 대의 PC 환경에서 프로그램을 개발했지만, 실제 서비스처럼 서로 다른 PC에서 메시지를 주고받을 수 있도록 구현하고자 했습니다.
이를 위해 처음으로 Microsoft Azure에 서버 환경을 구축했습니다.
서버를 직접 실행하고 종료하면서 연결 상태를 확인했으며, 서로 다른 PC에서 프로그램을 실행해 메시지가 정상적으로 송수신되는지 반복적으로 테스트했습니다.
연결 오류와 서버 설정 문제를 수정한 끝에 서로 다른 PC 간 채팅 통신을 구현했습니다.

### 배운 점
이 프로젝트를 통해 클라이언트, 서버, 데이터베이스가 각각 독립적으로 존재하는 것이 아니라 서로 연결되어야 하나의 서비스가 완성된다는 점을 처음으로 체감했습니다.
또한 이후 프로젝트에서 Azure와 서버 기술을 활용하게 된 계기가 되었습니다.

# 📌 Project 02
# 🤖 AI Robot Arm

### 프로젝트 개요
첫 번째 캡스톤 프로젝트에서 Raspberry Pi와 Arduino를 활용한 로봇팔을 제작했습니다.
카메라로 입력되는 영상에서 YOLO 객체 인식 기술을 활용해 물체를 구분하고, 인식 결과가 실제 로봇팔의 동작으로 이어지도록 소프트웨어와 하드웨어를 연동했습니다.
프로젝트 결과 장려상을 수상했습니다.

### 사용 기술
- Raspberry Pi
- Arduino
- Python
- YOLO
- Camera
- Embedded System
- Computer Vision

### 주요 구현 내용
- Raspberry Pi 기반 시스템 구성
- Arduino를 활용한 하드웨어 제어
- 카메라 영상 입력
- YOLO 객체 인식
- 객체별 분류
- 객체 인식 결과 전달
- 인식 결과와 로봇팔 제어 연동
- 소프트웨어와 하드웨어 통합

### 구현 과정
프로젝트에서는 객체를 인식하는 기능과 로봇팔을 움직이는 기능이 각각 동작하는 것만으로는 충분하지 않았습니다.
카메라에서 전달된 영상을 AI가 분석하고, 인식 결과가 제어 명령으로 연결되어 실제 로봇팔이 움직여야 했습니다.
팀원들과 객체 인식, 센서, 로봇팔 제어 등 역할을 나누어 개발했으며 각 기능의 연결 과정에서 발생한 문제를 지속적으로 공유하고 수정했습니다.
객체 인식 결과와 실제 로봇팔 동작이 일치하는지 반복적으로 테스트하면서 하나의 시스템으로 통합했습니다.

### 배운 점

이를 통해 AI와 임베디드 기술을 결합한 시스템에 관심을 갖게 되었습니다.

# 📌 Project 03
# 🍳 WellCook - AI 맞춤형 레시피 서비스

### 프로젝트 개요
WellCook은 사용자의 건강정보, 알레르기, 보유 식재료를 기반으로 맞춤형 레시피를 제공하는 서비스입니다.
단순 레시피 조회가 아니라 사용자의 상태와 현재 보유하고 있는 식재료를 활용해 더욱 적합한 레시피를 제공하는 것을 목표로 개발했습니다.
Android 애플리케이션, Spring Boot 서버, MySQL 데이터베이스, AI 식재료 인식 기능을 하나의 서비스로 연결했습니다.

### 주요 담당
- Backend
- Database
- API
- Android / Server 연동
- Azure 서버 배포
- 식재료 데이터 정리
- YOLOv8 식재료 인식

### 사용 기술

#### Backend
- Java 17
- Spring Boot
- Spring Data JPA
- REST API

#### Database
- MySQL

#### Android
- Android
- Java
- Retrofit2
- OkHttp

#### Cloud
- Microsoft Azure
- Azure VM

#### AI
- Python
- YOLOv8
- Roboflow
  
## 주요 기능
- 회원가입 및 로그인
- 사용자 정보 관리
- 건강정보 관리
- 알레르기 정보 관리
- 식재료 정보 관리
- 레시피 데이터 관리
- 보유 식재료 기반 레시피 추천
- 사용자 건강정보를 고려한 레시피 제공
- Android와 서버 간 API 통신
- Azure VM 서버 배포
- YOLOv8 기반 식재료 이미지 인식

## Backend & Database
Spring Boot와 MySQL을 활용해 서버와 데이터베이스를 구축했습니다.
회원, 식재료, 레시피 등의 데이터를 관리하고 Android 애플리케이션에서 필요한 정보를 REST API를 통해 제공할 수 있도록 구현했습니다.
개발 과정에서는 단순히 기능 하나를 만드는 것보다 어떤 데이터를 저장하고 어떤 형태로 전달해야 애플리케이션에서 활용하기 편한지를 고민했습니다.
앱과 서버를 연동하는 과정에서 API 오류와 데이터 불일치가 발생했을 때 Android → API → Spring Boot → MySQL의 흐름을 단계적으로 확인하며 문제의 원인을 추적했습니다.
이를 통해 서비스 전체 데이터 흐름을 이해하고 문제를 해결하는 경험을 쌓았습니다.

## Android & API
Android 애플리케이션과 Spring Boot 서버 간 통신을 위해 Retrofit2와 OkHttp를 활용했습니다.
Android에서 요청한 데이터를 서버에서 처리한 뒤 다시 애플리케이션으로 전달하도록 API를 구성했습니다.
로컬 환경에서 개발한 이후 Azure VM에 서버를 배포해 외부 환경에서도 Android 애플리케이션이 서버에 접근할 수 있도록 구성했습니다.
첫 번째 프로젝트에서 처음 경험했던 Azure 서버 구축 경험을 WellCook에서는 실제 모바일 서비스 환경으로 확장할 수 있었습니다.

## AI Food Recognition
사용자가 자신이 보유한 식재료를 하나씩 검색하고 직접 입력해야 하는 과정이 반복적이고 불편하다고 판단했습니다.
이를 개선하기 위해 YOLOv8을 활용한 식재료 이미지 인식 기능을 개발했습니다.

### 활용 기술
- Python
- YOLOv8
- Roboflow

### Dataset
총 5개의 식재료 클래스를 구성했습니다.

- Bean Sprout
- Egg
- Garlic
- Potato
- Tofu

총 1500장의 이미지 데이터를 정리하여 학습에 활용했습니다.
서로 다른 데이터셋을 병합하고 클래스별 이미지와 라벨을 확인했으며, 인식 결과가 좋지 않은 클래스의 데이터를 다시 확인하면서 모델 학습 과정을 반복했습니다.
이를 통해 사용자가 식재료를 직접 하나씩 입력하는 대신 카메라 이미지에서 식재료를 인식하고, 해당 데이터를 레시피 추천 기능으로 연결할 수 있는 기반을 구현했습니다.
